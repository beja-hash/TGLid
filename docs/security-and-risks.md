# Безопасность и реестр рисков

## Базовые меры

Минимально необходимые данные, RBAC и объектные права, зашифрованная Telegram-сессия/секреты, аудит действий, транзакционный outbox, блокировка диалога, стоп-лист, лимиты и глобальная пауза — обязательны. Секреты передаются через защищённое хранилище и никогда не попадают в логи, аналитические события, ошибки API или клиентский код.

### Реализованная защита backend-доступа

- Argon2id для паролей; email нормализуется и хранится в PostgreSQL `CITEXT`.
- Случайный raw session token существует только в `HttpOnly`, `SameSite=Lax` cookie; PostgreSQL хранит SHA-256 hash. В production обязательна cookie `Secure`.
- CSRF token случайный, привязан к конкретной серверной сессии и сверяется с hash для всех POST/PATCH, кроме login. Login принимает только `Origin` из конфигурации.
- Redis rate limit использует hash комбинации нормализованного email и IP. Email не виден в ключе, доверие к `X-Forwarded-For` не включено; при недоступном Redis вход fail-closed.
- Деактивация и reset пароля отзывают все сессии; самостоятельная смена пароля оставляет текущую сессию, отзывает остальные и ротирует CSRF.
- Операции, уменьшающие число активных администраторов, сериализуются transaction-scoped PostgreSQL advisory lock. Поэтому конкурентные изменения не могут оставить систему без активного `ADMIN`.
- Критическое изменение и audit event коммитятся одной транзакцией. Audit metadata проходит защитную фильтрацию и не содержит секретов.

### Frontend 2.2B

Интерфейс хранит в памяти только безопасный профиль пользователя. Он не читает HttpOnly session cookie, не использует JWT/localStorage и не логирует пароль или временный пароль. CSRF берётся только из специально выданной cookie и не взаимозаменяется с session token. Роль в React state управляет лишь навигацией; фактические права подтверждает backend. Audit metadata выводится React как текст JSON без HTML-инъекций.

## Операционные правила

- Любая критическая ошибка аккаунта, сессии, стоп-листа или неизвестного результата отправки блокирует повторную отправку до ручной проверки.
- Полный текст переписки доступен лишь по объектному праву; экспорт и просмотр фиксируются аудитом.
- Резервные копии, сроки хранения, правовые основания, удаление/маскирование данных и порядок реагирования на инциденты требуют утверждения до запуска пилота.
