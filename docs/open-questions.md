# Открытые вопросы заказчику

| Вопрос | Почему важен | Допущение по умолчанию | Риск неверного допущения |
|---|---|---|---|
| Какие услуги предлагает компания? | Определяет смысл диалога и передачу | Не обещать конкретную услугу | Нерелевантные/ложные обещания |
| Какие проблемы целевые? | Нужны категории и AI-порог | Только залив, протечка, авария, бездействие УК | Потеря лидов или лишние контакты |
| Какие группы допустимы? | Право на мониторинг и качество источников | Только явно утверждённый список | Нарушение правил/жалобы |
| Кто предоставляет аккаунт и подтверждает доступ? | Владение сессией и ответственность | Заказчик владеет аккаунтом | Потеря доступа/спор о владении |
| Кто утверждает скрипты? | Первый контакт и AI-политика | Администратор заказчика до пилота | Несогласованная коммуникация |
| Что считается готовой заявкой? | Статусы и метрики | Только явное согласие на созвон | Неверная воронка/KPI |
| За какой срок нужны три согласия? | Планирование пилота и бюджет | KPI не фиксировать без даты | Неуправляемые ожидания |
| Кто оплачивает AI и прочие переменные расходы? | Лимиты и отчётность | Заказчик, отдельный бюджет | Неконтролируемые траты |
| Максимальная сумма/период AI-расходов? | Аварийные лимиты | AI-ответы выключать при неутверждённом лимите | Перерасход |
| Какие сотрудники работают в системе? | Учётные записи и права | Минимум админ + сотрудник | Неавторизованный доступ |
| Нужно ли хранить телефон? | Минимизация персональных данных | Только если человек добровольно написал | Лишний риск ПДн |
| Нужна ли интеграция с CRM? | Объём данных и передача | Нет в MVP | Ручная потеря данных или лишний scope |
| Какие юридические ограничения применимы? | Законность контакта/хранения | Пилот не стартует без проверки | Нарушение закона/правил платформы |
| В какие часы можно писать? | Политика отправки | Не отправлять без утверждённого расписания | Жалобы/дискомфорт |
| Как обрабатывать отсутствие ответа? | Таймаут и повторный контакт | Не писать повторно | Нежелательная рассылка |
| Допускается ли одно повторное сообщение? | Нужен точный шаблон и срок | Нет до явного утверждения | Повторный контакт после отказа |
| Как фиксируется согласие на созвон? | Валидность `CALL_CONSENTED` | Явный текст в истории с ID сообщения | Ложная квалификация |
| Какие контакты/каналы допустимы для созвона? | Передача сотруднику | Только Telegram до добровольного контакта | Ненадлежащая обработка ПДн |
| Нужны ли уведомления и кому? | Операционный SLA | В интерфейсе, без внешних каналов | Пропуск срочного лида |
| Сколько активных диалогов разрешено? | Лимит нагрузки и безопасности | Низкий настраиваемый лимит до пилота | Перегрузка/риск жалоб |
| Какие причины `WON`/`LOST` обязательны? | Качество аналитики | Минимальный список утвердить | Невозможно оценить результат |
